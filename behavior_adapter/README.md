## 实现与输出

- `scene.py`：通过官方 Evaluator 恢复任务实例、加载 RGB-D，导出 `scene.json` 和首帧 RGB-D。
- `robot.py`：从实时 Fabric 变换读取碰撞网格；导出 `robot.json`、机器人坐标系碰撞点。
  `hold_action` 捕获上身目标；`navigation_action` 使用官方反缩放，将机体速度目标转换为动作。
  相机 K 与 optical-to-body 外参从当前传感器和底盘位姿读取。
- `route.py`：官方地面支持图与当前非地面碰撞三角形投影，按实测本体圆包络、10 cm 余量及
  栅格误差膨胀；采用与官方相同搜索顺序的稀疏四邻域 A*，只在同一安全栅格通过时简化直线段。
  自动选择同一连通区域内 1.5–2.5 m 的目标，用实际位姿闭环跟踪并检查非地面接触。
  折线插值为连续三次曲线，逐段密采样检查当前 R1Pro 地图；不安全的曲线明确拒绝。
  复用 CurveNav `timed_route` 曲率限速（0.25 m/s、0.30 rad/s），再做起停及纵向
  0.35 m/s² 限制的时间重参数化。速度时间进程再用 σ=0.2 s、±0.6 s 支持范围的
  高斯核平滑，重新按弧长映射到原曲线，并拉伸时间满足线速度/角速度上限。
  不滤波空间坐标，也不滤波实测结果。实际位姿反馈 + 速度前馈；命令平移/转向变化分别
  限制到 0.5 m/s²、1 rad/s²，反馈修正命令上限 0.30 m/s、0.50 rad/s。
  起步先对齐初始切线，之后连续走过拐点；终点位置 <5 mm、朝向误差 <2°，
  平移/转向命令已低于 0.005 m/s、0.01 rad/s 后，连续 10 帧零命令结束。
  终点朝向取末端切线。加速度参数是跟踪器设计值，不代表实测硬件极限。
- `test_scene.py`：训练实例边界与单次仿真运动检查；不引入新测试框架。

## H800 与共享目录并行

H800 和 aibox 使用同一份 `scene.py`、`collect.py`、`route.py`、任务计划和路线目录。
H800 只通过独立调度器指定卡位、CPU 亲和性和本机 BEHAVIOR 路径：

```bash
cd /shibo_huang/CurveNav
/opt/conda/bin/python -u behavior_adapter/dataset_h800.py \
  --task-min 50 --task-max 99 --gpus 0,1,2,3,4,5,6,7 \
  --slots 0,1,2 --slots-per-gpu 3 --run-id h800_50_99
```

两端按任务号分区；`run_scene.sh` 在共享目录给每个任务加锁，并在 `complete.json` 已发布时跳过。
`dataset_h800.py` 在 `h800_runs/<run-id>/` 写状态和显存记录，单任务失败会继续派发其他任务；
需要暂缓的任务用 `--skip-tasks 77,78`。重新运行时用新的 `--run-id`，已有路线按 `routes.jsonl`
续采，不重复写成功路线。

H800 的场景快照可能自带一个没有相机的机器人。启动参数
`CURVENAV_REPLACE_SCENE_ROBOT=1` 使共享加载器在场景导入前跳过它，再加载官方评测配置中的机器人，
并过滤接触矩阵未登记的场景碰撞列；aibox 的默认路径不启用这项兼容逻辑。
距离档的 100 个候选都失败时，采集器按长→中→近、中→近或窄→近依次尝试，输出分别记录
`requested_band` 和实际 `band`。
`task_077.json` 和 `task_078.json` 已将各 13 条无法满足的长距离请求改为中距离；
实际仍不可达的请求由上述统一规则继续降级，路线记录不伪称原距离档。

## H800 训练现有安全轨迹

`train_existing_h800_10ep.py` 先核对审计和冻结的路线清单，再编译训练缓存，
按用户要求从每卡 batch 512 开始，依次尝试 448、384、320、256，
